# MyLife

Проект о том, как составить хороший план на день с учётом типа человека, профессии и хобби и равномерно распределить работу, спорт, семью и детей. Сейчас здесь исследование и системный подход «Система 168». Дальше в этом же репозитории будут программы, которые помогают применять эту систему.

## Структура репозитория

```
MyLIfie/
├── README.md        ← этот файл: что за проект и где что лежит
├── CLAUDE.md        ← правила репозитория для сессий Claude Code
├── .gitignore       ← общие исключения для всех программ
├── docs/            ← исследования, отчёты, ментальные карты
├── apps/            ← программы: каждая в своей папке
└── packages/        ← общий код, который используют несколько программ
```

Это монорепозиторий: все программы проекта живут вместе, пока они связаны одной темой и меняются вместе. Правила для программ — в [apps/README.md](apps/README.md), для общего кода — в [packages/README.md](packages/README.md).

## Система 168 в двух словах

1. **Профиль** — режим работы, хронотип, потребность в структуре, подотчётность, социальная энергия, особенности внимания.
2. **Фундамент** — сон от подъёма назад, якоря детей, минимум движения: эти блоки не двигаются.
3. **Смысл** — роли, ценности, 2–4 цели на квартал.
4. **Неделя** — 168 часов, «большие камни» по ролям в календарь первыми, недельный обзор и семейное совещание.
5. **День** — скелет по энергии (пик → спад → восстановление → закрытие → семья), формула «1 + 3 + 3 + 1», буфер 20–40 %.
6. **Исполнение** — техника фокуса под профиль, «если–то», пакетирование, заметки возобновления.
7. **Обратная связь** — день, неделя, месяц, квартал.

## Как работать с Git в этом репозитории

- `main` — основная ветка: в ней всегда рабочее состояние.
- Новая работа идёт в отдельной ветке и попадает в `main` через Pull Request.
- Имя ветки начинается с типа и программы: `feat/planner-week-view`, `fix/bot-reminders`, `docs/report-update`.
- Версии программ отмечаются тегами с префиксом программы: `planner-v1.0.0`, `bot-v0.3.0`.

## Когда выносить программу в отдельный репозиторий

Только при конкретной причине: нужны разные права доступа, часть становится открытой, программа живёт независимо и почти не меняется вместе с остальными, её код нужен другим проектам, тяжёлые данные или особые требования безопасности. Благодаря границам папок программу можно вынести вместе с историей коммитов (`git subtree split` или `git filter-repo`).
