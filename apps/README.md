# Программы

Каждая программа проекта лежит в своей папке внутри `apps/`. Пока программ нет: первая появится здесь, когда начнётся её разработка.

```
apps/
├── planner-web/       ← пример: веб-планировщик дня
│   ├── README.md
│   ├── package.json   ← или pyproject.toml, go.mod и т. п.
│   ├── src/
│   └── tests/
└── telegram-bot/      ← пример: бот-напоминалка
```

## Правила

1. **Одна программа — одна папка.** Имя папки короткое, латиницей, через дефис: `planner-web`, `telegram-bot`, `mobile`.
2. **У каждой программы свой README** с ответами на вопросы: что она делает, как её запустить, как запустить тесты, какие переменные окружения нужны.
3. **У каждой программы свой файл зависимостей** (`package.json`, `pyproject.toml` и т. п.). Программу можно собрать и проверить, не трогая соседние папки.
4. **Программы не импортируют код друг друга напрямую.** То, что нужно нескольким программам, переносится в [`packages/`](../packages/README.md).
5. **Секреты не коммитятся.** Пароли и ключи хранятся в `.env`, файл `.env` в `.gitignore`. В репозиторий кладётся только `.env.example` с пустыми значениями.
6. **Ветки и теги с префиксом программы:** ветка `feat/planner-week-view`, тег `planner-v1.0.0`.
7. **Автопроверки по папке.** Когда появятся GitHub Actions, каждая программа получает свой файл в `.github/workflows/` с фильтром `paths: ["apps/<имя>/**", "packages/**"]`: изменение одной программы не запускает проверки остальных.

## Как добавить новую программу

1. Создайте ветку: `git switch -c feat/<имя>-init`.
2. Создайте папку `apps/<имя>/` с README и файлом зависимостей.
3. Добавьте строку о программе в таблицу ниже.
4. Откройте Pull Request в `main`.
